# 06 角色独立脚本评分

## 目标

为 MVP 角色实现独立的固定函数评分体系，让玩家赛后能看到本局表现参考。

## 范围

本阶段只做脚本评分，不调用 LLM。评分必须基于时间轴、玩家视角和赛后解密结果，不能凭空生成评价。

## 评分输出

每局结束后应生成：

- 0 到 100 的总分。
- 当前角色专属分项评分。
- 每个分项的简短解释。
- 引用到的时间轴事件 id。
- 正向亮点。
- 负向或高风险时刻。

## 通用评分问题

每种角色评分都应回答：

- 玩家行为是否符合角色定位。
- 玩家是否帮助己方阵营。
- 玩家是否打击敌方阵营。
- 玩家是否在关键回合做出有效选择。
- 如果赢了，哪些行为和分析是出彩点。
- 如果输了，哪些行为起到了反作用。

## 角色评分维度

平民：

- 站边判断。
- 投票贡献。
- 发言有效性。
- 生存价值。
- 误导风险。

预言家：

- 查验目标价值。
- 报信息时机。
- 带队贡献。
- 隐藏或跳出时机。
- 投票贡献。

女巫：

- 救药价值。
- 毒药价值。
- 信息判断。
- 出手时机。
- 避免误伤。

狼人：

- 刀人目标价值。
- 伪装质量。
- 抗推压力制造。
- 队友配合。
- 对好人阵营的干扰效果。

## 必要接口

创建评分契约，例如：

```ts
scorePlayerGame(input: PlayerScoringInput): RoleScore
scoreVillager(input: PlayerScoringInput): RoleScore
scoreSeer(input: PlayerScoringInput): RoleScore
scoreWitch(input: PlayerScoringInput): RoleScore
scoreWerewolf(input: PlayerScoringInput): RoleScore
```

`PlayerScoringInput` 可以使用赛后数据，但只能在游戏结束后生成。

## 测试要求

添加测试覆盖：

- 每个 MVP 角色都能获得评分。
- 评分包含总分和分项拆解。
- 评分引用时间轴事件。
- 同一份复盘的评分是确定性的。
- 有帮助的投票会提高相关分项。
- 毒中狼人会提高女巫评分。
- 毒到好人会扣除女巫评分。
- 预言家查验高影响力可疑目标会获得奖励。
- 狼人推动好人出局会获得奖励。

## 验收标准

- 玩家完成对局后可以获得角色专属评分。
- 评分不需要 API key。
- 每条解释在可行时至少引用一个时间轴事件。
- 脚本评分明确标注为确定性脚本评分。

## 不在本阶段范围

- 自然语言 AI 教练复盘。
- 难度系统。
- MVP 以外的新角色。
