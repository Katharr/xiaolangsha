# 06 角色独立脚本评分

## 目标

为 MVP 角色实现独立的固定函数评分体系，让玩家赛后能看到本局表现参考。

## 范围

本阶段只做脚本评分，不调用 LLM。评分必须基于时间轴、玩家视角和赛后解密结果，不能凭空生成评价。

## MVP 最小评分模型

MVP 阶段评分目标是“可解释、可追溯、够用”，不是追求复杂专家系统。先使用 4 个统一顶层维度，每个角色对这 4 个维度有不同解释和计算方式。

| 维度 | 权重 | MVP 含义 |
| --- | ---: | --- |
| `角色定位契合度` | 30 | 玩家行为是否符合当前角色应该承担的职责。 |
| `阵营贡献` | 30 | 玩家行为是否帮助己方阵营，是否打击敌方阵营。 |
| `信息利用与判断` | 20 | 玩家是否有效利用自己当时可见的信息，包括公开信息和角色私有信息。 |
| `发言与投票影响` | 20 | 玩家公开发言、身份表达、投票和带队行为是否产生正向影响。 |

每个维度必须引用明确的时间轴事件作为证据。没有事件支撑的维度不能给出有效分数，必须返回低置信度或不可评分状态，并解释缺少哪些事件。

## 评分输出

每局结束后应生成：

- 0 到 100 的总分。
- MVP 固定 4 个分项评分。
- 每个分项的简短解释。
- 引用到的时间轴事件 id。
- 正向亮点。
- 负向或高风险时刻。

## 通用评分问题

每种角色评分都应回答：

- 玩家行为是否符合角色定位。
- 玩家是否帮助己方阵营。
- 玩家是否打击敌方阵营。
- 玩家是否在关键回合做出有效选择。
- 如果赢了，哪些行为和分析是出彩点。
- 如果输了，哪些行为起到了反作用。

## 角色映射说明

平民：

- `角色定位契合度`: 是否像平民一样基于公开信息找狼、避免乱跳身份和制造无效混乱。
- `阵营贡献`: 投票、发言、站边是否帮助好人阵营推进。
- `信息利用与判断`: 是否利用死亡、发言、票型和身份声明做判断。
- `发言与投票影响`: 是否通过发言或投票影响局势，避免成为抗推位。

预言家：

- `角色定位契合度`: 查验、报信息、隐藏或跳出是否符合预言家职责。
- `阵营贡献`: 查验和报信息是否帮助好人阵营找到狼人或排清好人。
- `信息利用与判断`: 是否结合自己的查验结果、公开发言和票型判断局势。
- `发言与投票影响`: 报查验、带队、投票是否帮助好人形成有效共识。

女巫：

- `角色定位契合度`: 救药、毒药、隐藏身份和出手时机是否符合女巫职责。
- `阵营贡献`: 药水使用是否保护好人、打击狼人、减少误伤。
- `信息利用与判断`: 是否合理利用夜晚死亡提示、公开发言、票型和药水状态。
- `发言与投票影响`: 是否通过发言和投票配合好人阵营，而不是暴露神职或误导好人。

狼人：

- `角色定位契合度`: 是否完成伪装、扰乱好人、保护或利用队友、推动抗推。
- `阵营贡献`: 刀人、发言、投票是否帮助狼人阵营接近胜利。
- `信息利用与判断`: 是否利用狼队信息、公开发言、票型和神职线索选择行动。
- `发言与投票影响`: 是否通过发言和投票带偏好人、制造错误共识或减轻队友压力。

## 必要接口

创建评分契约，例如：

```ts
scorePlayerGame(input: PlayerScoringInput): RoleScore
scoreVillager(input: PlayerScoringInput): RoleScore
scoreSeer(input: PlayerScoringInput): RoleScore
scoreWitch(input: PlayerScoringInput): RoleScore
scoreWerewolf(input: PlayerScoringInput): RoleScore
```

`PlayerScoringInput` 可以使用赛后数据，但只能在游戏结束后生成。

评分结果必须满足以下结构约束：

```ts
type RoleScore = {
  totalScore: number;
  dimensions: ScoreDimension[];
  highlights: ScoreMoment[];
  risks: ScoreMoment[];
};

type ScoreDimension = {
  name: "角色定位契合度" | "阵营贡献" | "信息利用与判断" | "发言与投票影响";
  score: number | null;
  weight: 30 | 20;
  summary: string;
  evidenceEventIds: string[];
  confidence: "high" | "medium" | "low" | "unscorable";
};
```

`RoleScore.dimensions` 在 MVP 阶段必须固定为 4 项。每个 `ScoreDimension.evidenceEventIds` 必须非空，且只能引用赛后时间轴中真实存在的事件。缺少证据事件时，`score` 必须为 `null` 或低置信度分数，`confidence` 必须说明不可评分或低置信度原因。

## MVP 后扩展策略

原先的细分维度保留为 MVP 后候选项，不进入 MVP 固定评分模型：

- 平民候选项：站边判断、投票贡献、发言有效性、生存价值、误导风险。
- 预言家候选项：查验目标价值、报信息时机、带队贡献、隐藏或跳出时机、投票贡献。
- 女巫候选项：救药价值、毒药价值、信息判断、出手时机、避免误伤。
- 狼人候选项：刀人目标价值、伪装质量、抗推压力制造、队友配合、对好人阵营的干扰效果。

新增任何评分维度前，必须先定义该维度依赖哪些时间轴事件。禁止新增无法从时间轴解释的主观评分项。

## 测试要求

添加测试覆盖：

- 每个 MVP 角色都能获得评分。
- 每个 MVP 角色都能生成固定 4 个评分维度。
- 每个维度都有至少一个 `evidenceEventId`。
- `evidenceEventIds` 引用的事件必须存在于赛后时间轴。
- 同一份复盘的评分是确定性的。
- 缺少证据事件时，该维度必须返回可解释的低置信度或不可评分状态，不能凭空打分。
- 每个角色至少有一个固定 replay 用例，证明评分维度和时间轴事件能对应起来。
- 有帮助的投票会提高 `发言与投票影响` 或 `阵营贡献`。
- 毒中狼人会提高女巫的 `阵营贡献`。
- 毒到好人会降低女巫的 `阵营贡献`。
- 预言家查验高影响力可疑目标会提高 `信息利用与判断`。
- 狼人推动好人出局会提高 `阵营贡献` 和 `发言与投票影响`。

## 验收标准

- 玩家完成对局后可以获得角色专属评分。
- 评分不需要 API key。
- MVP 阶段每个角色固定输出 4 个评分维度。
- 每个评分维度都有明确时间轴事件支撑。
- 没有时间轴事件支撑的维度不能给出有效分数。
- 脚本评分明确标注为确定性脚本评分。

## 不在本阶段范围

- 自然语言 AI 教练复盘。
- 难度系统。
- MVP 以外的新角色。
