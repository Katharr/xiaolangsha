# 01 R1 LLM 玩家协议与信息隔离

## 目标

定义 LLM AI 玩家的最小协议，让模型可以作为 AI 玩家认知核心，同时确保本地规则引擎仍是唯一权威裁判。

本阶段的重点不是可玩 UI，而是数据契约、边界、校验器和信息隔离测试。

## 范围

本阶段实现或修订：

- `LlmPlayerView`
- `LegalActionOption`
- `LlmPlayerDecisionCandidate`
- LLM 请求载荷构建器
- LLM 响应解析器
- 决策候选校验器
- LLM 失败重试和弱脚本兜底接口
- 多视角信息泄露矩阵测试

本阶段不实现：

- 完整 UI 对局体验。
- 自由文本发言。
- 深度复盘。
- 多模型 provider 选择。
- 新板子或新角色。

## 协议原则

LLM 只能收到：

- 当前 AI 玩家的身份、阵营目标和存活状态。
- 当前阶段和轮次。
- 当前 AI 规则上可见的私有信息。
- 公开时间轴摘要。
- 公开发言和投票历史。
- 合法行动列表。
- 自己上一轮可见立场和行动摘要。

LLM 不能收到：

- 完整 `GameState`。
- 其他玩家真实身份，除非规则允许。
- 当前视角外的查验结果、药水状态、夜间行动。
- `internal` 事件。
- 随机种子。
- 调试快照。

## 决策候选最小字段

`LlmPlayerDecisionCandidate` 至少包含：

- `actionType`
- `targetId`
- `speechIntent`
- `speechText`
- `stance`
- `suspicion`
- `trust`
- `reasoningSummary`
- `usedEvidenceEventIds`
- `confidence`

候选不是权威行动。只有通过本地校验后，才能转换为规则引擎可提交的 `Action`。

## 校验规则

校验器必须拒绝：

- 不在合法行动列表内的行动。
- 不存在或不可选的目标。
- 引用不可见事件的理由。
- 泄露隐藏身份、未公开查验、药水状态或夜间选择的发言。
- 把猜测写成规则事实。
- 包含“我是 AI”“系统提示要求我”等出戏内容。
- 因玩家元话术而放弃角色目标。

失败处理顺序：

1. 要求 LLM 根据结构化错误重试。
2. 重试失败后使用本地弱脚本兜底。
3. 将失败原因写入 `internal` 时间轴事件。

## 验收标准

- LLM 请求 payload 不包含完整 `GameState`。
- 平民 LLM 视角看不到任何隐藏身份。
- 狼人 LLM 视角只知道狼队友，不知道神职身份。
- 预言家 LLM 视角只知道自己的查验结果。
- 女巫 LLM 视角只知道规则允许的夜晚信息和药水状态。
- LLM 决策候选不能绕过合法行动列表。
- LLM 输出非法时不会污染规则状态。
- 多视角信息泄露矩阵测试覆盖 LLM 请求上下文。
