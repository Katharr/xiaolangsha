# 02 规则引擎和完整时间轴

## 目标

实现 6 人 MVP 对局的规则引擎，并记录完整时间轴。

## 范围

本阶段实现可完整跑完一局的状态转移和时间轴记录。完整对局测试使用确定性测试脚本或 fixture actions 推进，不实现真实 AI 策略；UI 可以暂时不完整，但规则引擎必须可测试。

本阶段的“完整跑完一局”只证明规则状态转移、胜负判断和时间轴记录正确，不代表已经完成脚本 AI。AI 玩家决策留到 `specs/03-script-ai-opponents.md`。

## 必要流程

实现以下阶段：

- 设置
- 夜晚
- 白天发言
- 白天投票
- 放逐结算
- 游戏结束

夜晚行动：

- 狼人选择一个刀人目标。
- 预言家查验一个存活玩家。
- 女巫每局可以救人一次。
- 女巫每局可以毒人一次。
- MVP 规则：女巫同一晚不能同时实施救人行为和毒人行为。

白天行动：

- 公布死亡结果，但不公开身份。
- 每个存活玩家记录一次结构化发言意图。
- 记录投票。
- 结算放逐。
- 如果平票，在平票玩家之间进行一次重新投票。
- 如果仍然平票，则无人出局。

## 胜利条件

实现两种模式：

- `side_elimination`: 全部狼人死亡时好人胜利；全部平民或全部神职死亡时狼人胜利。
- `total_elimination`: 全部狼人死亡时好人胜利；全部好人死亡时狼人胜利。

MVP UI 默认使用 `side_elimination`，但测试必须覆盖两种模式。

## 时间轴要求

每个有意义的事件都必须按顺序记录：

- 对局创建。
- 角色分配作为赛后事件记录。
- 阶段变化。
- 夜晚行动请求。
- 夜晚行动提交。
- 私密夜晚结果送达。
- 公开死亡结果公布。
- 发言意图记录。
- 投票提交。
- 投票结果结算。
- 放逐结算。
- 胜利条件检查。
- 游戏结束。

### 事件类型可见性清单

本阶段必须把事件类型和可见性枚举为代码常量或类型联合，不允许用自由字符串临时拼接。MVP 至少包含下表：

| 事件类型 | 对局中可见性 | 赛后可见性 | 说明 |
| --- | --- | --- | --- |
| `game_created` | `public` | 可见 | 规则集、座位数、胜利模式。 |
| `role_assigned` | `private` 给对应玩家；狼人队友另见 `wolf_team_revealed` | `post_game` 全部可见 | 对局中只给本人。 |
| `wolf_team_revealed` | `wolf_team` | `post_game` 可见 | 只给狼人阵营。 |
| `phase_changed` | `public` | 可见 | 阶段变化。 |
| `night_action_requested` | `private` 给行动者；狼人阶段给 `wolf_team` | 可见 | 请求行动，不泄露给无关玩家。 |
| `night_action_submitted` | `private` 给行动者；狼人刀人给 `wolf_team` | `post_game` 可见 | 提交目标和行动类型。 |
| `seer_check_result` | `private` 给预言家本人 | `post_game` 可见 | 查验结果。 |
| `witch_death_prompt` | `private` 给女巫本人 | `post_game` 可见 | 女巫按规则看到的夜晚死亡信息。 |
| `witch_potion_state_changed` | `private` 给女巫本人 | `post_game` 可见 | 药水状态变化。 |
| `night_death_announced` | `public` | 可见 | 公布死亡，不公布身份。 |
| `speech_intent_recorded` | 行动者 `private` 或仅 `post_game` | `post_game` 可见 | 结构化意图；对局中他人只看发言文本。 |
| `speech_rendered` | `public` | 可见 | 公开发言。 |
| `vote_submitted` | MVP 默认 `public` | 可见 | 若后续匿名投票，需改为延迟公开事件。 |
| `vote_result_resolved` | `public` | 可见 | 票型、平票、重投结果。 |
| `exile_resolved` | `public` | 可见 | 放逐结果；MVP 默认不公开身份。 |
| `win_condition_checked` | `internal` | 可用 `post_game` 摘要展示 | 对局中不可见，避免泄露屠边/屠城进度。 |
| `game_over` | `public` | 可见 | 公布获胜阵营。 |
| `post_game_role_reveal` | 对局中不可见 | `post_game` 可见 | 游戏结束后揭晓全部身份。 |
| `ai_decision_reason` | 对局中不可见 | `post_game` 可见 | 赛后解释 AI 行动理由。 |
| `coach_question` | `private` 给人类玩家 | 可按设置进入复盘 | 玩家问题。 |
| `coach_advice` | `private` 给人类玩家 | 可按设置进入复盘 | 教练建议。 |
| `llm_request_payload` | `internal` | 默认不可见 | 仅开发调试，必须脱敏。 |
| `system_seed_or_rng` | `internal` | 默认不可见 | 随机种子和内部调试信息。 |

### 对局中不可见的信息

以下内容在游戏结束前不得出现在公开时间轴、无关玩家私有时间轴、局内教练上下文或 LLM 上下文中：

- 其他玩家真实身份。
- 未公开查验结果。
- 女巫药水剩余状态和夜晚选择，除女巫本人视角外。
- 狼队刀人选择，除狼人阵营视角外。
- `win_condition_checked` 的隐藏中间状态。
- AI 内部怀疑分、策略权重、未公开决策理由。
- 完整 `GameState`、随机种子、调试快照。

每个事件必须包含：

- 稳定事件 id。
- 阶段。
- 第几天或第几晚。
- 行动者，如果适用。
- 目标，如果适用。
- 可见性。
- 公开摘要。
- 结构化载荷。

时间轴必须支持：

- 玩家局内视图
- AI 局内视图
- 教练玩家视角上下文
- 赛后复盘视图

## 测试要求

添加测试覆盖：

- 一局完整 6 人游戏可以进入游戏结束。
- 非法目标会被拒绝。
- 死亡玩家不能行动或投票。
- 预言家只收到私密查验结果。
- 女巫使用药水后药水状态会变化。
- 公开时间轴不会泄露隐藏身份。
- 赛后时间轴可以揭示所有身份和隐藏行动。
- `side_elimination` 下，狼人杀光全部平民可以获胜。
- `side_elimination` 下，狼人杀光全部神职可以获胜。
- `total_elimination` 下，狼人只有杀光全部好人才可获胜。
- 必须新增或更新 `multi-view-leakage` 测试，覆盖本阶段新增的夜晚行动、查验、女巫药水、发言、投票、胜负检查和赛后解密事件。

### 多视角泄露测试要求

该测试必须在一局包含以下事件的固定对局上运行：

- 狼人提交刀人目标。
- 预言家获得查验结果。
- 女巫收到夜晚死亡提示，并至少使用一次药水。
- 白天产生公开发言和投票。
- 至少触发一次 `win_condition_checked`。
- 游戏结束后产生 `post_game_role_reveal`。

测试必须证明：

- 对局中公开视图看不到狼人刀人目标、预言家查验结果、女巫药水状态、真实身份、`win_condition_checked` 内部细节。
- 狼人视图能看到狼队友和狼队夜晚选择，但看不到神职身份。
- 预言家视图能看到自己的查验结果，但看不到未查验玩家身份。
- 女巫视图能看到规则允许的夜晚死亡提示和自己的药水状态，但看不到狼人身份或刀人来源。
- 教练视图只等同人类玩家视角，不会因为是教练而获得额外上帝信息。
- 赛后复盘视图能看到 `post_game` 解密信息。
- 所有玩家、AI、教练、LLM 视图都不包含 `internal` 事件、完整 `GameState`、随机种子或调试快照。

## 验收标准

- 一个确定性测试可以模拟完整对局。
- 完整对局测试由 fixture actions 或确定性测试脚本驱动，不依赖真实 AI 策略。
- 游戏结束后，时间轴可以还原所有玩家决策和结果。
- 已实现公开和私有时间轴过滤。
- 胜利条件逻辑支持屠边和屠城。
- 多视角信息泄露矩阵测试覆盖本阶段新增事件并通过。

## 不在本阶段范围

- 高级 AI 策略。
- 角色评分。
- 教练 UI。
- LLM 调用。
- 扩展角色。
