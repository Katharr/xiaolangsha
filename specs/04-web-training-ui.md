# 04 Web 训练界面

## 目标

做出可玩的 Web 单机训练界面，让玩家能完整玩完 6 人屠边局。

## 范围

本阶段实现游戏桌、行动面板、发言记录、投票面板和基础结算入口。评分、完整复盘、教练和 LLM 不在本阶段完成。

## 体验原则

- 首屏就是游戏桌，不做营销落地页。
- 界面服务训练和对局，不堆装饰。
- 玩家始终能看清：自己是谁、现在是什么阶段、能做什么、已经发生了什么。
- 玩家始终能看懂：为什么进入当前阶段、为什么产生当前结算、下一步应该看什么反馈。
- 移动端也要能完成一局。

## MVP 体验验收故事

玩家完成一局时，界面必须支持以下连续体验：

1. 开始新游戏，并看清 `quick-6-v1` 和屠边规则。
2. 确认自己的人类玩家座位和角色。
3. 在每个阶段看到明确的可执行行动，无法行动时看到等待或说明。
4. 夜晚行动、白天发言和投票都能通过行动面板完成。
5. AI 自动推进其他玩家行动时，玩家能看到公开信息流更新。
6. 关键结算后，界面解释“发生了什么”，但不泄露隐藏身份。
7. 游戏结束后，玩家能进入评分和复盘入口，为 `specs/06` 和 `specs/07` 的反馈闭环预留位置。

## 必要视图

游戏设置：

- 开始新游戏。
- 选择人类玩家座位或随机座位。
- 如果规则集设置支持，则选择人类玩家角色或随机角色。
- 显示规则集名称 `quick-6-v1`。
- 显示胜利模式 `屠边`。

游戏桌：

- 6 个座位。
- 存活/死亡状态。
- 公开玩家编号。
- 玩家自己的角色。
- 如果玩家是狼人，显示已知狼队友信息。

行动面板：

- 夜晚行动选择。
- 发言选择或发言输入占位。
- 投票选择。
- 确认行动。

信息流：

- 公开阶段变化。
- 公开死亡公布。
- 发言文本。
- 投票结果。

游戏结束：

- 获胜阵营。
- 进入后续复盘/评分页面的入口。

## 数据规则

UI 必须从 `PlayerView` 或派生 UI 视图模型渲染，不能直接读取完整 `GameState`。

## 测试要求

添加 UI 测试或组件测试覆盖：

- 可以开始新游戏。
- 玩家能看到自己的角色。
- 游戏结束前，玩家看不到隐藏角色。
- 玩家可以提交合法夜晚行动。
- 玩家可以在白天投票。
- 游戏可以通过 UI 流程进入结束状态。
- 玩家能通过 UI 理解当前阶段、可用行动、关键结算和下一步入口。
- 移动端视口不会阻塞核心行动。

## 验收标准

- 玩家可以在浏览器里完成一局 6 人 `quick-6-v1`。
- 玩家在一局中始终能看清“我是谁、到哪一步、能做什么、为什么这样结算、下一步看什么反馈”。
- 游戏结束前 UI 不泄露隐藏身份。
- 不需要 API key。
- `npm test`、`npm run build` 和 Playwright 冒烟测试通过。

## 不在本阶段范围

- 完整角色评分页面。
- 教练聊天。
- AI 赛后复盘。
- LLM 发言。
- 扩展规则集。
