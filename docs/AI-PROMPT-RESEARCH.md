# AI 玩家提示词调研沉淀(为重构提供依据 + 未来扩展)

> 配套 `docs/AI-PROMPT-REDESIGN.md`。本文记录两类调研:① 参考项目 `oil-oil/wolfcha` 的提示词做法;② 学界/业界「persona-first 角色扮演 + 社交推理博弈」的提示词最佳实践。供本次重构与未来演进(尤其 wolfcha 式「每局现生成人设」)参考。

## 一、参考项目:oil-oil/wolfcha 的 AI 提示词做法

仓库:https://github.com/oil-oil/wolfcha (Next.js + TS,统一 LLM 网关,支持 DeepSeek/Qwen/Gemini/Kimi 等)。关键源文件:
- `src/i18n/messages/zh.json` / `en.json` —— 完整提示词模板库(所有 prompt 在此)
- `src/lib/character-generator.ts` —— 两阶段角色生成调度
- `src/lib/ai-config.ts` —— 温度配置 + 模型路由
- `src/game/phases/*` —— 各阶段(发言/夜晚/投票)prompt 组装

### 1. 两阶段「先做人」角色生成(每局现生成、局内固定、跨局重生)
- **阶段一 `baseProfilesPrompt`(基础档案)**:`displayName`(2-3字名)、`gender`、`age`、`mbti`、`basicInfo`(职业/身份一句,如「开了十年出租的老司机」「互联网产品经理」)。提示词强调「这是玩狼人杀的普通人,不是悬疑剧本角色」,禁动漫式夸张口癖,口头禅偶尔用、像口语。
- **阶段二 `fullPersonasPrompt`(深层人设,温度最高 1.2)**:基于阶段一档案,生成两组隐藏维度:
  - **persona(表层人设,7 维)**:`werewolfExperience`(对游戏的理解程度)、`vocabularyStyle`(用词/术语密度)、`reasoningStyle`(最先注意什么:听感/票型/身份收益…)、`speechLengthHabit`(平时/被质疑/归票时长短变化)、`pressureStyle`(被怀疑时反应)、`uncertaintyStyle`(如何表达不确定)、`mistakePattern`(惯犯错误/盲点)、`wolfDeceptionStyle`(拿狼牌怎么伪装)。
  - **playerMind(打法心智,6 维)**:`courage`(胆量:敢不敢诈/硬推/冲票)、`memoryBias`(更记得票型/矛盾/语气/身份声明/时机)、`suspicionThreshold`(几条线索改站边、哪类最有效)、`selfProtection`(被攻击时解释/反打/装委屈/沉默/转移)、`logicDepth`(单点 vs 串联票型身份)、`tablePresence`(占话/短促/插话/潜水/关键时强势)。
  - 约束:全用自然描述,不写 high/low/新手/高手 标签,不写字数区间;隐藏字段只进提示、不上 UI。

### 2. 提示词装配顺序(「先做人、再玩游戏」的结构体现)
身份框架(座位+名字)→ 角色设定(persona 表层)→ 场景背景(职业)→ 胜负条件 → 当前局势(存活/死亡/票/查验)→ 历史关键事件 → 任务指令。**人设排在局势与任务之前**,让 AI 先以「这个人」的身份理解局势再行动。

### 3. 温度分层(`ai-config.ts`)
角色生成 1.2(WILD)、发言 1.1(CREATIVE)、行动/投票 0.4(LOGIC)、历史总结 0.1(STRICT)。→ 发言要自然多样,行动要逻辑优先。

### 4. 其它要点
- 20 个场景模板(同学聚会/年夜饭/婚礼/创业公司/医院急诊/电竞战队…)决定起名风格与职业背景;人物在局中只聊狼人杀本身,不聊场景剧情。
- 发言指令明确「不需要完美、不需覆盖所有人」,允许坦诚/含糊/试探/反驳/带节奏/保护/隐藏;严禁编造不存在的发言/票/查验/死亡。
- 投票指令含身份立场检查:预言家优先投确认的狼;好人不能无视单边预言家查验、可信玩家归票、明确对跳;狼可伪装站边但别自爆式选择。
- 每局现生成 → 跨局新鲜;局内固定 → 一致可信,玩家能学会「这个人通常怎么玩」。

## 二、学界/业界最佳实践(persona-first 的证据)

| 来源 | 关键结论 |
|---|---|
| Role-Play Prompting (arxiv 2308.07702) | 角色扮演式提示在推理基准上 +10~60%(AQuA 53.5→63.8,Last Letter 23.8→84.2);「先两轮建立角色再提问」优于单轮;角色扮演本身是比「逐步思考」更有效的隐式思维链触发器 |
| Thinking in Character / RAR (arxiv 2506.01748) | 把角色约束**注入推理步骤本身**(情感/经历/立场/动机),人物一致性成为思考过程的涌现属性,而非事后修补;解决「注意力转移」与「风格漂移」 |
| Talk Less, Call Right (arxiv 2509.00482) | 可靠的工具/动作调用必须**先于**自然对话;显式规则(硬约束)优于隐性学习 → 动作执行要 task-first |
| Private Deliberation (PMC11203171) | 启用「私有内部推理 + 公开战略隐瞒」的 agent 长期收益显著更高(部分博弈约 2 倍);提示要明确分离内部思维与公开表达 |
| AmongAgents (arxiv 2407.16521) | 规划/记忆/行动多样性 > 固定人物;故意的知识缺陷/会犯错增强拟人;结构化三步:总结过去→定策略→选行动 |
| OpenCharacter (arxiv 2501.15427) | 人物卡标准字段:名字/年龄/性别/职业/出生地/经历/性格;多样化人设是跨域角色泛化的必要条件;小模型微调可逼近 GPT-4o |
| RL Werewolf (arxiv 2310.18940) | RL 策略可从强模型迁移到弱模型(LLaMA-7B 等);用「生成多样行动候选 + 轻量策略选择」而非微调;预定义多种人物风格(3 狼 + 3 民)增强鲁棒 |
| Probing via Werewolf (werewolf.foaster.ai) | 私有/公开分离;同一模型的「狼人格」与「村民人格」从角色激励中涌现 |
| awesome-llm-role-playing-with-persona (GitHub Neph0s) | 角色扮演资源汇总 |

**综合结论(指导本次重构)**:
- persona-first 在「思维/推理/拟人」层面优于 task-first → **人物卡领头**。
- 但动作执行/JSON/合法目标要 task-first 硬约束 → **输出契约与任务纪律保持严格**。
- 私有(真实推理,狼可含欺骗)/公开(人设一致、隐藏意图)分离 → 用 `analysisSummary` vs `text`。
- 给原则而非枚举场景,结构化要点,缺点增强拟人,适配弱模型。

## 三、未来扩展路线:wolfcha 式「每局现生成人设」

当前项目选了**固定老朋友·静态丰富**(见 REDESIGN 决策)。若未来要演进到 wolfcha 式现生成:
- 新增一个生成 taskType(开局调一次 LLM 产出整桌人设),复用本文阶段一/二字段设计。
- **必须把生成结果持久化进存档(Dexie)**,否则刷新恢复/复盘无法保持人设一致(破坏现有确定性/复现纪律)。
- 可引入场景模板(如同学聚会/创业公司)调节起名与职业风格。
- 代价:开局多一次 LLM 调用(成本+延迟);失去「跨局认识的老朋友」体验(可做成可选模式)。
- 当前静态人物卡(`NAME_CHARACTERS`)的字段设计与此对齐,可平滑迁移。
