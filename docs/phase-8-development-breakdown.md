## 阶段8目标

第一轮可运行骨架目标：在无美术素材的单页 Web 聊天室中跑通 5 人最简局，从开局到首夜、白天、投票/平票、死亡旁观/快进和终局复盘，且局中只展示 `VisibleInformationSnapshot` 允许的信息。

阶段8只定义开发切片与审查规则。阶段9才允许 Developer Agent 创建 React/Vite/TypeScript 应用、源码目录、测试和运行脚本。

## 锁定决策

1. 阶段9按 `S8-SLICE-*` 顺序推进，每个切片必须独立实现、独立验证、独立审查。
2. `Agent.md` 是治理依据全集；`Skill.md` 是默认最小启动读取规则；每个切片任务单必须列出追加文档。
3. 每个切片必须绑定阶段6验收编号，不得只写验收类别。
4. 每个切片必须声明负路径要求，不得只做 happy path。
5. `ISO-001` 与 `ISO-002` 在阶段9全程为红线验收；任何破坏必须驳回。
6. 第一轮可运行骨架只在 `S8-SLICE-12` 完成并经 Reviewer Agent 通过后触发阶段10 `HITL-001`。
7. 阶段9 Developer Agent 不得修改阶段1至阶段8锁定规则；若发现规则不足，先提交回溯清单。

## 待验证事项

1. 阶段9真实执行时，需要验证切片粒度是否足够小，是否能让 Developer Agent 与 Reviewer Agent 稳定交接。
2. 阶段9执行过程中，需要验证每个切片的测试命令和证据是否足以支撑 Reviewer 独立判断。
3. 阶段10 `HITL-001` 需要验证第一轮骨架是否真的具备“一个人能玩下去”的基础体验。

以上事项只影响阶段9和阶段10执行，不影响阶段8开发拆分的进入条件。

## 切片顺序与依赖

推荐顺序：

`S8-SLICE-01 -> S8-SLICE-02 -> S8-SLICE-03 -> S8-SLICE-04 -> S8-SLICE-05 -> S8-SLICE-06 -> S8-SLICE-07 -> S8-SLICE-08 -> S8-SLICE-09 -> S8-SLICE-10 -> S8-SLICE-11 -> S8-SLICE-12`

依赖关系：

1. `S8-SLICE-02` 是所有业务切片前置。
2. `S8-SLICE-03` 至 `S8-SLICE-06` 先完成规则闭环。
3. `S8-SLICE-07` 在规则事件稳定后接入。
4. `S8-SLICE-08` 依赖 `S8-SLICE-03` 至 `S8-SLICE-07`。
5. `S8-SLICE-09` 可在 `S8-SLICE-08` 后独立补强 AI 契约。
6. `S8-SLICE-10` 依赖 Store 可用。
7. `S8-SLICE-11` 依赖规则闭环、UI 壳和 AI/review 边界。
8. `S8-SLICE-12` 只做整体验证与交付，不新增业务范围。

## 阶段9切片流转

1. Developer Agent 按任务单读取默认文档与追加文档，声明切片编号和验收编号后实现。
2. Developer Agent 提交变更与交付说明，附验证命令或可重复证据、未覆盖项、已知限制和 HITL 判断。
3. Reviewer Agent 独立审查，不直接替 Developer 修改代码，输出通过单或驳回单。
4. 若驳回，Developer Agent 按驳回单修正并重新提交，Reviewer Agent 复审同一切片证据。
5. 普通切片通过后进入下一切片，暂不触发项目负责人 HITL。
6. `S8-SLICE-12` 通过 Reviewer Agent 审查后，进入阶段10并触发 `HITL-001`。

阻断规则：缺少验收编号、缺少证据、破坏信息隔离、违反模块边界，必须驳回。若发现上游文档矛盾，先提交回溯清单。
